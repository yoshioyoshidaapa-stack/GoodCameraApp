# HuskyLens 2 (DFRobot SEN0638) を ESP32 の MicroPython から使う

`huskylens2.py` は、DFRobot 公式の Arduino 用部品
(https://github.com/DFRobot/DFRobot_HuskylensV2) の通信の決まりを読んで、
MicroPython に書き直した小さな部品です。

## 状態

- **実機で動作を確認しました**（利用者の報告：「動いた」。画面に出た細かい状態は、記録していません）。
- 確認した組み合わせ：ESP32（ESP-WROOM-32、ideaspark 1.14インチ LCD 基板）+ HUSKYLENS 2（ファームウェア 1.4.2）+ HUSKYLENS 2 Power Board V1.0.0。
- 実機で見つかった不具合：MicroPython に無い `bytearray.pop()` を使っていて、`knock` の段階で AttributeError になりました。直して、再発防止の試験（`test_display.py` の `test_no_micropython_incompatible_calls`）を追加しました。
- `test_huskylens2.py` と `test_display.py` は、パソコンの Python で動かす試験です。MicroPython との違いは、すべては拾えません。

## 鳥の画面（既定のモード）

画面の見本（近似）：`docs/display_mock_bird.png`

- 認識の種類は、**物体認識（80種類）**。この中の「bird」だけを探します（名前が `bird` の結果だけを数える）。
- 画面の左に、カメラの視野（640×480）を 1/4 にした「地図」が出て、鳥の位置に、黄色い枠が出ます（鳥が2羽なら、2つ）。
- 画面の右：`BIRD`、鳥の数（`x2`）、いちばん大きい鳥の自信（`60%`）、その位置（`x500 y300`）、写真の状態（`PH:ON 1`）、見えた物の名前（`bird,pers…`）、Bluetooth の状態。
- 鳥が見えたら、写真を撮ります（顔のときと同じ。10秒に1回まで、最大50枚）。撮る直前に、地図の上に「SHOOT」と出ます。
- **BOOT ボタンを4秒以上押し続ける**と、鳥 ⇔ 顔 のモードが切り替わります。選んだモードは、基板の `mode.txt` に残ります（なければ、鳥）。
  - 短押し（1.5秒未満）：写真の入り切り / 1.5〜4秒：自動登録の入り切り（顔認識のときだけ）
- ※ **実機では、まだ試していません。** 特に、物体認識の結果の「名前」に、本当に `bird` と入るか、位置（x、y、幅、高さ）が出るかは、未確認です。
  確かめる道具：`hl_object_debug.py`（結果を、そのまま表示する）。画面の右の「見えた物の名前」の行でも、確認できます。
- 物体認識は、「鳥」という種類までです。「スズメか、ハトか」の見分けは、できません（公式 Wiki）。

## 画面の機能（顔認識の画面。時計の表示はやめた）

画面の見本（近似。文字の形は実機と違います）：`docs/display_mock.png`

- 画面の割り当て（240×135）：一番上に人の呼び名（大きい文字）、その下に色の帯、顔の数と ID の一覧、写真の状態、自動登録の状態、詳細、Bluetooth の状態。
- 時刻は、いまも BLE で受け取れます（Android アプリは、そのまま使えます）。ただし、画面には出しません。
- **写真を撮るときは、画面の一番上に「SHOOT」と、大きく出ます**（色の帯も白）。撮影の間は、画面の更新が止まるので、撮る直前に描きます。
  次に結果を読むまで（約1秒）、そのまま出ます。

- **人ごとの表示**：一番大きい行に、見えている顔の人の呼び名が出ます（いちばん大きい顔＝いちばん近い人）。
  - まだ覚えていない顔（ID 0）：`unknown`（白）
  - 名前を付けた顔：その名前（英数字のみ。日本語などは、画面の文字で出せないので ID 表示）
  - 名前がない顔：`ID 1`、`ID 2` …
  顔の数と、見えている全員の ID は、下の小さい行に出ます（例：`n=2 ids=1,0 x320 y240`）。
- **人ごとの色**：ID ごとに、画面の色の帯と、人の呼び名の色が変わります。
  ID 0 は白、1 は赤、2 は緑、3 は青、4 は黄、5 は紫、6 は水色、7 は橙。8 以上は、最初に戻って繰り返します。
  顔がなければ、灰色の帯です。
  - **顔を覚えさせないと、どの顔も ID 0（白）のままです。** 覚えさせ方（公式 Wiki）：HuskyLens2 で顔認識を選び、
    顔が白い枠で囲まれたら、画面の中央の十字を枠の中に合わせて、本体の右上の「Button-A」を押す。
    覚えた顔は、画面に「Face: ID1 97%」のように出る。
- **顔が見えたら写真を撮る**：顔が見えている間、10秒に1回まで、写真を撮らせます（電源を入れてから最大50枚）。
  基板の「BOOT」ボタンで、入り切りできます。画面の「PHOTO ON/OFF  枚数  ファイル名」で、状態が分かります。
  - 写真の保存先は、公式 Wiki によると、HuskyLens2 内蔵の USB ドライブの `storage/photo` です（マイクロ SD に保存されるかは不明）。
  - 写真の解像度は 640×480（`photo_res=1`）。撮影の間、時計の更新が最大 2.5 秒止まることがあります。
  - 顔の写真を自動で保存するので、プライバシーに注意してください。間隔や上限は `hl_status.py` の引数で変えられます。
- ※ どちらも、パソコン上の試験（ニセの機械）で確かめた段階です。本物の HuskyLens2 では、まだ試していません。

- **知らない顔を自動で覚えさせる（ID01、ID02 … の順）**：ESP32 から、HuskyLens2 に「覚えろ」（learn）の命令を送ります。
  次の条件が、すべて、3回続けて（約3秒）そろったときだけ、覚えさせます。
  - 見えている顔が、1つだけ。
  - その顔が、まだ覚えていない顔（ID 0）。
  - 顔の幅が、80 以上（画面の幅 640 のうち）。
  - 画面の中央の十字が、顔の枠の中にある（本体の Button-A と同じ条件）。
  覚えさせたら、画面に「NEW ID01」と、5秒だけ出ます。前の登録から10秒は、次を登録しません。電源を入れてから、最大8人までです。
  - 同じ人が、角度や明るさで、別人として、何度も登録される可能性があります（防ぎきれません）。
  - 覚えた ID が、電源を入れ直したあとも、残るかは、未確認です。
  - 知らない人の顔を、自動で登録する機能です。使わないときは、OFF にしてください。
- **ボタン（基板の「BOOT」）**：短く押す = 写真の入り切り、1.5秒以上押す = 自動登録の入り切り。
  画面の一番下に、「ENR ON 2」（自動登録 ON、これまでに2人）のように、出ます。
- ※ これらは、パソコン上の試験（ニセの機械）で確かめた段階です。実機では、まだ試していません。
  特に、`learn` の命令が、本物の HuskyLens2 で、どの顔を覚えるか、ID がどの順に付くかは、未確認です。

## ESP32 を再起動(EN ボタン)すると、HuskyLens2 が固まる問題

- 症状（利用者の報告）：ESP32 の EN ボタンを押すと、HuskyLens2 が固まって、電源を入れ直さないと、正常に動かない。
- 原因：**未確認**。ESP32 が、通信の途中で消えて、HuskyLens2 の I2C が、続きを待つ状態で止まる、という予想です。
- 入れた対策（実機では、まだ試していません）：
  1. 起動したら、最初に、I2C のバス復旧（SCL を最大9回動かして、STOP を送る）をする（`hl_status.bus_clear`）。
  2. 全住所を探す `scan()` をやめて、HuskyLens2 の住所 0x50 だけに、公式の部品と同じ読み方（16バイト）で触れる。
  3. I2C を使い始める前に、1秒待つ。
- 調べる道具：`hl_line_check.py`（固まったときの SDA/SCL の状態と、バス復旧の結果を表示する）。
- 追加の観察（利用者の報告）：EN ボタンを押すと、HuskyLens2 が、いったん、モード選択画面に戻り、そのあと、顔認識に切り替わると、
  カメラの映像が出ず、顔認識の表示と、黒い画面になる。電源を入れ直せば、正常に戻る。
  `hl_step.py`（接続確認、結果の要求、切り替え、もう一度の切り替え）では、固まらなかった。赤い線（+）を外しても、変わらなかった。
- 次の予想（未確認）：メニューに戻る途中で、すぐ「顔認識に切り替え」を送ると、カメラの準備が間に合わない。
  対策として、接続確認（knock）のあと、**4秒待ってから**切り替えるようにした（`knock_settle_ms`）。
- 結果（利用者の報告）：接続確認のあと、待ってから切り替える対策で、**映像が出るようになった**。
  ただし、画面の表示が、「connecting」と「not found」を、交互に繰り返した。
- 次の予想（未確認）：「顔認識に切り替え」の返事が、モデルの読み込みで遅れて、0.6秒では待ちきれず、失敗と判断して、つなぎ直していた。
  対策：knock は1.5秒、切り替えは3秒まで待つ。切り替えの返事が届かなくても、すぐにはつなぎ直さず、結果が読めるかで判断する
  （結果が5回続けて読めなければ、つなぎ直す）。
- 切り分け用：`hl_knock_test.py`（8秒待つ）と `hl_knock_nowait.py`（待たない）。先に顔認識の画面にしておいて、実行する。
- それでも直らなければ、HuskyLens2 の電源を、ESP32 とは別に、入り切りできるようにする、などの回避策が必要です。

## 配線（実機で動いた形。赤い線は、外したまま）

詳しくは `docs/wiring.png`（`docs/wiring.svg`）を見てください。

| 色付きケーブル | 電源ボード Gravity 端子 | ESP32 基板 |
|---|---|---|
| 緑 | D/T（SDA） | D21 |
| 青 | C/R（SCL） | D22 |
| 黒 | −（GND） | GND |
| 赤 | +（入力） | **つながない（外したまま）** |

- 赤い線なしで、実機で動きました（利用者の報告）。経緯：EN での症状の切り分けで、赤を外しても、症状は変わらなかったので、外したまま使っています。
- HuskyLens2 は、白い4ピンケーブルで、電源ボードの「I2C/UART」端子につなぐ。
- 電源ボードの「PWR IN」に、USB-C で電源を入れる（HuskyLens2 の電気は、ここだけから取る）。
- 電源を入れる順番：先に電源ボードの USB 電源 → HuskyLens2 の起動を待つ → そのあと ESP32 の USB。
- 根拠：DFRobot フォーラムの回答（I2C では D/T = SDA、C/R = SCL）。
  https://www.dfrobot.com/forum/topic/403800

## 分かっていること

### 公式の Wiki で確認したこと (https://wiki.dfrobot.com/sen0638/)

- 動作電圧は 3.3〜5V、消費電力は 1.5〜3W。
- 通信は、工場出荷の状態で I2C。住所は `0x50`。
  UART で使うときは、HuskyLens2 の画面の「システム設定」→「Protocol Type」で切り替える。
- 通信の方式は、UART/I2C の端子のそばの表示灯で見分けられる。I2C は青、UART は緑。
- 配線は、4ピンのジャンパーケーブル（またはデュポン線）を使う。
- **電源に関する注意（公式の Arduino の説明より）**: Arduino Uno の I2C 端子の出力電圧では、
  HuskyLens2 を動かすには足りない。HuskyLens2 の USB-C 端子に、別に USB-C ケーブルをつないで電源を入れる。
  電源ボード（HUSKYLENS 2 Power Board）を使う方法も、公式が勧めている。

### 公式の Arduino 用部品(コード)より

- I2C の住所は `0x50`、速度は 100kHz。
- 公式の部品が対応するファームウェアは 1.4.2 以上。
- 公式の部品は UART でも使えるが、この部品は I2C のみ。

## まだ確認していないこと

- 信号線（D/T、C/R）が、何ボルトでつり上げられているか。公式の回答では、直接は触れられていません。実機は、動いています。
- 赤い線なしでの、信号線の電圧の基準。長時間の動作（熱、電源の不足）。
